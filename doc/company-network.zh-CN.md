# 公司网络扫码连接

适用于 Android 11 及以上：手机与 Mac 可通过 IP 互通，但公司网络禁用了跨网段 mDNS，普通扫码配对一直转圈。

Anmir Connect 在手机本机发现调试端口，再回传给 Mac；之后仍使用 Android 系统的配对验证。无需修改公司网络配置，也无需每次填写 IP 或端口。

## 首次安装

1. 在 Mac 的 Anmir 点击 Wi-Fi 加号，进入扫码窗口。
2. 选择 **公司网络连接**，点击 **打开下载页**，在浏览器打开对应版本的 GitHub 发布页。也可以从[发布列表](https://github.com/houzi3/Anmir/releases)选择与 Mac 版本对应的 Anmir Connect APK；或点击 **扫码安装**，使用手机相机扫描弹出的二维码直接下载对应版本。这里不要使用“无线调试”的扫码入口。已安装辅助应用时可跳过此步。
3. 将安装包传到手机，用系统文件管理器打开并安装。如果系统询问，允许该来源安装应用。
4. 已有 USB 或 Wi-Fi ADB 连接时，也可以使用命令安装：

   ```sh
   adb -s DEVICE install -r path/to/AnmirConnect.apk
   ```

安装只需进行一次；以后正式版可覆盖更新。

如果之前安装过同包名的测试 APK，请先卸载测试版再安装正式版。正式版采用固定发布签名，之后的正式更新可覆盖安装；卸载测试版后需重新扫码保存 Mac。

Android 应用包名为 `io.github.houzi3.anmir.connect`。旧测试版的 `io.github.laobie.anmir.connect` 属于另一个应用，迁移时可在新版安装成功后卸载旧版，避免重复图标。

## 首次扫码连接

1. 保持 Mac 的 **公司网络扫码连接** 窗口打开。Mac 有多个网卡地址时，选择手机可以访问的地址。
2. 点击手机上的 **Anmir Connect** 图标打开 App，再点击 **启动辅助连接**。页面中的步骤编号为 **1.**、**2.**。
3. 辅助服务真正就绪后，会出现 **辅助连接已启动** 弹窗，约 1.2 秒后自动打开开发者选项并尝试定位“无线调试”。
4. 进入 **无线调试 → 使用二维码配对设备**，扫描 Mac 上的当前二维码。
5. 配对成功后，Mac 自动打开投屏。手机收到 Mac 确认后保存回传凭据，显示“已开启自动重连”。该状态表示自动重连已启用，实际投屏结果以 Mac 为准。

使用系统无线调试的扫码入口，保持无线调试开关开启。手机辅助组件本身不提供相机扫码。

Anmir Connect 会尝试自动滚动到并高亮“无线调试”条目；部分厂商系统可能忽略定位参数，此时在开发者选项中手动点击“无线调试”即可。

开发者选项在系统设置自己的任务栈中打开，与 Anmir Connect 分开；从最近任务切回 Anmir Connect 时会保留页面和运行状态，也不会重复跳转。运行期间可以点击 **打开开发者选项** 或 **停止辅助连接**。停止辅助组件不会关闭无线调试，也不会断开已经建立的投屏。

## 断网后的自动重连

需要 Anmir Connect **0.1.2 或更高版本**与 Mac 版 Anmir **0.1.2 或更高版本**。首次成功扫码后，无需每次重新扫码：

- 保持手机辅助连接和 Mac 的 Anmir 运行。手机断开 Wi-Fi 时等待网络，恢复后重新发现本机调试端口并回传；Mac 验证已配对设备身份后重连。
- 断网前正在投屏时，恢复连接后重新打开投屏。主动关闭投屏窗口会取消这次自动恢复。
- 暂时连不上 Mac 时按 2、4、8、16、30 秒逐步重试，最多每 30 秒一次。点击手机 **立即重试** 可跳过当前等待；没有保存过 Mac 时不显示此按钮。
- **停止辅助连接** 暂停回传和重连，保留保存的 Mac；再次启动可继续使用。**忘记已保存的 Mac** 清除手机保存的回传凭据，下次需重新扫码；它不会删除 Android 系统中已配对的 ADB 信任。

二维码本身仍在 5 分钟后过期。配对前，辅助服务也有 5 分钟上限；保存 Mac 后不再自动超时，并显示可随时停止的持续通知。

若系统关闭无线调试，仍需手动开启。Mac 地址变化、端口被其他程序占用、公司网络阻止两端互通时，自动重试无法代替重新扫码或恢复网络。辅助组件被强行停止或手机重启后需重新启动；系统省电可能延迟后台网络，解锁手机或返回 App 后可点击“立即重试”。当前手机只记住最近成功扫码的一台 Mac，Mac 最多保存 8 台手机。

## 遇到问题时

| 现象 | 操作 |
| --- | --- |
| 二维码过期，或等待时间较长 | 刷新 Mac 二维码；辅助组件已停止时重新启动，再从系统入口扫码。未完成首次配对的二维码和辅助服务最多有效 5 分钟。 |
| 提示签名不兼容，无法覆盖安装 | 先卸载同包名的早期测试版，再安装正式 APK，并重新扫码。 |
| 启动失败 | 先连接 Wi-Fi，再重试。失败时不会弹出启动成功提示，也不会自动进入设置。 |
| 无法访问 Mac | 检查 Mac 是否允许 Anmir 访问本地网络、接收入站连接，并确认手机可以访问所选 Mac 网卡地址。 |
| Mac 配对窗口不可用 | 首次扫码时重新打开公司网络扫码窗口，刷新二维码再扫。已开启自动重连时，只需保持 Mac 的 Anmir 运行。 |
| Wi-Fi 恢复后没有重连 | 确认无线调试仍开启，辅助组件和 Mac 的 Anmir 正在运行；点击“立即重试”。Mac 地址已变化时重新扫码。 |
| 未自动打开开发者选项 | 手动进入“设置 → 开发者选项 → 无线调试”。辅助服务已成功启动时可继续使用。 |
| 扫码仍持续转圈 | 确认辅助组件正在运行、二维码未过期，且使用的是系统无线调试扫码入口。 |
| 普通扫码没有发现设备 | 等待后可选择 **公司网络连接**，或选择 **修复连接** 并确认重启 Mac 的 ADB 服务。重启可能暂时中断其他设备的投屏和调试；重启后请扫描新二维码。未发现设备并不表示网络一定禁用了 mDNS。 |

此方式解决服务发现受限；设备隔离、防火墙或其他策略若阻止手机与 Mac 互通，仍会连接失败。当前回传通道使用 IPv4。

## 验证范围

公司内网跨网段扫码链路已于 2026-10-26 在 OnePlus KB2000 / Android 14 上验证：断开原 Wi-Fi 调试连接后，重新扫码触发配对、连接并自动投屏，无需手动输入地址或端口。

Pixel 7 / Android 16 已验证启动反馈、无线调试条目定位、设置独立任务栈和页面布局。自动化测试覆盖回传认证、端口变化、退避重试、设备身份校验、重连恢复与主动关闭投屏；实际后台网络调度仍受 Android 系统和厂商省电策略影响。
